# Live Media 0.1.1：点击播放与 ICC 照片压缩修复

本次修复针对已安装 0.1.0 的实际反馈。旧版本复检报告保留原验收事实；本文件单独记录新增回归和设备验证状态。

## 问题与修改

### 点击后进入静态放大图

0.1.0 在窗口捕获 `click`，但图片查看器可以在更早的 `pointerdown` / `mousedown` 打开放大视图，原缩略图因而失去后续点击。此事件竞争已在浏览器回归中复现，尚不能据此断言用户实际 Obsidian 的唯一根因。

0.1.1 在已确认的实况缩略图上捕获按下事件，记录播放手势并阻止宿主提前接管，随后由真正的点击启动播放。没有 `preventDefault` 按下事件，仍保留浏览器默认拖拽与焦点行为。普通图片、明确放行的 Alt 点击、菜单和文字说明继续走宿主路径。卸载后撤掉所有事件处理。

默认普通点击是原位播放，再次点击停止；Alt 点击可交给原来的图片查看器。宿主放大视图内的独立图片不是本轮新增的实况播放宿主。此前声明的“查看器优先”仍须配置替代播放手势；不承诺任何第三方在窗口上抢先处理事件时都能接管。

### `ICC JPEG reencode is not color-validated`

旧版本遇到普通 JPEG 的 ICC 配置就全局禁止处理。只读检查反馈样例确认普通照片具有 P3 的 RGB matrix ICC，实况片段为 H.264 / AAC；私人照片仅在本地读取格式信息，没有上传或重新编码。

新增 ICC 分片排序、完整性与有界标签解析，识别 sRGB / Display P3 的 RGB matrix 配置。普通照片重编码原样保留 ICC 的每个字节；随后在相应色域的浏览器 Canvas 上比较编码前后颜色，检查尺寸、RGB 均方根差异和每通道平均偏移。若 Canvas 不支持目标色域、资料不完整或比较失败，保留原件并拒绝提交。

实况的 `video-only` 路线不重编码静态照片：仅修改受支持的 XMP 长度值和嵌入视频；XMP 之外的照片、ICC、gain map、附加资源和 MPF 字节保持一致，继续检验视频音轨、帧时刻及封面时刻。未知 ICC 色域仍不能进入照片重编码路线，不再因它存在就禁止已验证的实况视频单独压缩。

色彩比较采用最长边 512 像素的有界取样，归一化 RGB RMS 上限 0.06，平均通道偏移上限 0.012。它是拒绝明显色偏的工程保护，不能当作逐像素无损或专业色差认证。ICC JPEG 缩放和未知色域仍保护跳过；最低节省比例、更大输出拒绝规则和最终确认保持有效。

## 更新及用户复测

正常退出 Obsidian。解压本次候选，将 `main.js`、`manifest.json`、`styles.css` 覆盖当前已经安装的 Live Media 目录内同名文件，保留已有 `data.json`；不要另建第二份相同 ID 插件。完整候选 ZIP 同时提供许可证资料。

重新打开 Obsidian，确认设置列表版本是 0.1.1。先测试阅读模式与 Simple Gallery 中有 LIVE 标识的图片：普通点击原位播放，再点停止；自动播放应静音，普通图片维持原查看行为。然后运行当前文章压缩，先看临时对比，用默认副本保存验证结果。

原始知识库文件、媒体及其他插件设置本轮只读。独立测试库使用本次下载产物；实际 Obsidian、移动端、宿主放大图和真实照片写回没有被 CI 浏览器测试替代，仍需用户确认。

## 依据

实现色彩空间与 Canvas 读取依据 HTML Standard 的 [color spaces and conversion](https://html.spec.whatwg.org/multipage/canvas.html#colour-spaces-and-colour-correction)、MDN 的 [getImageData](https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D/getImageData) 与 [createImageBitmap](https://developer.mozilla.org/en-US/docs/Web/API/Window/createImageBitmap)。此处列的是实现依据，不是设备通过证明。
