# Live Media 0.1.4：区分临时结果与实际保存

## 本机只读核对

2026-10-07 核对用户指定相册：150 张原图 SHA256 与原始迁移清单一致，0 个 `-compressed` 副本，配置的 `.live-media-reports` 和 `.live-media-backups` 均不存在。因此本机尚没有这些照片的提交或替换证据；不能把临时压缩预览的成功称为已经保存。没有推测用户点击行为，也没有自动压缩或改写原图。

当前设置仍是默认 copy，确认生成副本后文章引用保持原件。原地压缩需要由用户明确选 replace 并确认；此前的“成功”文案与保存入口的位置不足以解释这种差别。

## 改动

- 选择范围面板和结果面板直接展示“保存方式”：生成副本，或备份后替换原图。
- 读取与编码结束明确显示“临时结果已校验，尚未保存”；数量标为临时结果，关闭丢弃临时结果。
- 结果面板顶部固定放置保存方式、行为说明和单个确认按钮，不要求滚动整批预览才能找到保存入口。
- 副本确认按钮为“确认保存压缩副本”；原图模式为“确认替换原图（先备份）”，说明路径、名称和文章引用不变。
- 保存面板逐文件更新实际写入与读回结果，统计真实成功、失败和未处理数量，仅 committed 记录计入已保存及大小统计。
- 对比面板在保存面板成功打开后才关闭；本轮继续沿用指纹冲突、备份校验、保存读回和文件身份保护。

没有改全局默认输出模式，没有替用户确认覆盖，没有重压私人图片，没有改写文章引用、原图或其他插件配置。当前运行的 Obsidian 需重启后加载更新。
