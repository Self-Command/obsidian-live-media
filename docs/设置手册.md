# Live Media 设置与操作

本插件不上传媒体、不自动压缩、不移动图片，也不删除未引用附件。

## 照片播放

原图保留。支持的实况只增加 LIVE 标识和无控件的动态层。默认点击从头播放一次，可有声音；再次点击停止；Escape 停止。自动首次可见预览最多三秒，始终静音。后台、离开可视范围或卸载停止。

若查看器需要普通点击，将手动播放改为双击、长按或组合键点击，再设置查看器优先。实况优先时 Alt 点击默认交还宿主。普通图片、标题、右键菜单不由 Live Media 接管。

浏览器可能拒绝声音或无法调整音量；插件不会绕过系统限制，也不会给自动预览解除静音。

## 四步压缩

1. 从命令选择当前文章或全库范围；文件菜单可检查选定图片，选定文件范围支持搜索并添加多张图片。存在未保存正文时先保存。
2. 查看清单。动态展示、未知语法和共享原件需要主动选择；不把无法关联的 Blob、缩略图或远端链接猜成原件。
3. 临时编码后查看原件与结果；两侧实况仍直接点击照片播放。取消不写入。
4. 确认保存。默认同目录 `-compressed` 副本，不改文章引用。替换保留原路径、名称和扩展名，并先保存和读回核验备份。

较大输出、达不到节省门槛、未知索引、动画或无法保护的必要元数据明确跳过。全库是扫描范围，不表示所有格式都能安全压缩。

## HDR、Apple 与特殊格式

JPEG Motion Photo 默认只压缩视频，图片资源与 HDR 增益图保留。双重压缩和照片单独压缩仅在写入与保护验证通过的路线开放。可信 Apple 配对需要照片 MakerApple 身份、影片 QuickTime 身份和必要定时元数据一致；仅同名不是证明。

HEIC/HEIF/AVIF、动画和未验证的厂商布局保留原件。独立手机相册能否识别输出必须经过实机验收，浏览器能播放不是相册兼容证明。

## 偏好与后端

所有字段来自同一份 schema；支持搜索、默认值、单项／分组重置、预设、JSON 结构化编辑、导入前差异预览、平台与单照片覆盖。

继承顺序：全局 → 平台 → 明确开启的笔记 `live_media` → 单照片 → 批次。路径、程序授权及其他安全项不能由笔记或照片覆盖突破。

例如笔记 frontmatter 可以填写：

```yaml
live_media:
  auto.mode: off
  compression.jpegQuality: 90
```

先开启 `settings.overrideNotes`。文章命令使用该笔记覆盖；全库命令没有唯一来源笔记，只使用全局、平台与单照片偏好。编码预览前冻结每个文件的有效配置。输出方式、范围、共享策略和重复处理策略是批次决定，不能被笔记或照片覆盖。

副本不会自动切换文章引用；检验后可以主动引用副本。更改已经有副本的输入或参数时，换一个副本后缀或新目录，已有路径不覆盖。同输入和配置且副本仍有正确指纹时，不重复编码。

自动后端只选择已经通过保护门槛的路线。内置引擎离线加载，第一次压缩才初始化。WebCodecs 在没有通过时间与音轨保护前不会冒充可用后端。

本机 FFmpeg 只适用于桌面：填写程序绝对路径后，运行“授权本设备 FFmpeg”并确认该路径。同步 `native.enabled` 不等于授权另一台设备执行程序；导入不会授予执行权。程序以参数数组调用，无 shell 命令拼接。

## 恢复

“检查日志并恢复原件”列出本插件拥有的备份。恢复仅在当前文件仍等于本批次输出指纹时执行；用户后续修改会形成冲突，不覆盖。

存在修改或损坏输出时，可用“导出原件副本”保存校验过的备份到新路径，再人工比较。详细步骤见[恢复说明](恢复说明.md)。

备份位于 `.live-media-backups`，事务报告位于 `.live-media-reports`，通过 DataAdapter 访问。不要依赖隐藏目录一定被同步服务上传。保留天数只提示主动检查，不自动删除。

## 实机待验证

本轮由 Actions 构建和自动测试。本机测试库仅安装下载并核验的产物。真实 Obsidian、Simple Gallery、Android/iOS 的声音、滑动、后台与相册识别需由用户确认；正式发行前保留候选状态。


## 0.1.4 面板保存状态

“临时结果已校验，尚未保存”只说明内存中的压缩结果可供比较，原文件此时完全没变。只有选择保存方式并点确认，显示“已保存并读回校验”，才说明磁盘文件已经保存。

希望文章直接使用压缩图片：在选择范围或结果面板的保存方式中选“备份后替换原图，文章使用压缩图”，再点“确认替换原图（先备份）”。路径、文件名、扩展名及正文引用保持不变。默认副本模式不切换正文引用。
