# Live Media 0.1.2：真实批次压缩与资源释放

本轮针对用户反馈的 `Aborted()`、解码失败和后续图片连锁失败。实测时间按 Asia/Shanghai 为 2026-10-07 02:09—02:12，对应 GitHub/浏览器证据中的 2026-10-06 18:09—18:12 UTC。

## 修改

- 普通 JPEG 默认压缩改用固定版本 libjpeg-turbo 的独立接口，逐行完整解码，质量参数直接映射到 JPEG quality；保留输入色度采样，输出后保留原 ICC / EXIF，继续做浏览器色彩比较。
- 编码、验证失败即丢弃 Worker；每个媒体结束后释放整个编码器实例，阻止上张照片的峰值堆和错误状态继续留在下一张。
- 视频验证禁用自动旋转，以原方向完成全部帧解码；`wrapped_avframe` 避免额外生成整帧 rawvideo 缓冲。实际压缩仍保留并核验原方向矩阵。
- Motion Photo 编码显式保留原电影／视频时间单位，避免把 1/10000 秒的源电影时间单位降为 1/1000 秒后无法精确恢复。只有在所有帧展示时刻、帧数、尺寸和方向已一致时，才恢复末帧的原始时长；重建样本表和偏移后，再完整解码并校验音轨、色彩与时间。不能修复的布局仍保护跳过。
- 批次不再累计持有全部原图字节；仅保留临时结果和原件指纹。对比图滚动到可见区域才加载，离开或关闭后释放对象 URL 和播放资源；预览与提交时重新读取并核验原图。替换仍先备份、读回核验，原图有后续修改就拒绝覆盖。

没有降低原件指纹、完整解码、ICC 色彩、音轨、时间和默认 5% 节省比例的保护门槛。默认生成副本，不在源相册里试验覆盖。

## 本地实拍验证方式

用户指定相册全部复制到独立测试库，SHA256 核验。照片及带文件名的逐项结果仅保留在本机测试库，不提交公开仓库、CI 或远端服务。

`scripts/private-media-check.cjs` 启动独立 headless 浏览器，只允许访问随机令牌保护的 localhost 端点；加载从指定 Actions 下载并核验 SHA256 的 harness。每张编码、校验和输出均来自已构建的插件服务代码，不本地重新编译，不修改下载包。

序列验证调用相同 Compressor；批次验证调用实际 BatchService 的 prepare / commit，以默认副本输出并读回。CI 的合成样例和本机的私人实拍验证分别列出，不以浏览器测试冒充 Obsidian 或手机验收。

## 原件与更新

测试前后再次核验源相册及测试副本指纹。插件替换前核验 Obsidian 已正常退出，保留用户 `data.json`、启用状态和非目标插件；旧安装备份至桌面。最终实际 Obsidian 的图库点击、滚动预览和手机相册仍由用户实测确认。


## 当前安装与复测

当前库只替换 Live Media，保留 data.json 的原始字节和启用列表。旧 0.1.1 完整安装保存在桌面独立备份；替换后 279 个非目标 Obsidian 文件及 107 个库内 Markdown 指纹一致。未在当前库添加测试文章、报告、压缩副本或备份。

默认设置继续为 JPEG 质量 85、不缩放、Live 只压视频、保留 EXIF / GPS、最低节省 5%、默认同目录副本、跳过本插件已处理且指纹与设置一致的文件。选择副本时，文章引用继续指向原件；覆盖需要明确选择替换模式，插件会先验证备份。

重新打开 Obsidian 后，确认 Live Media 显示 0.1.2，在原文章运行当前文章压缩。先查看对比，再确认保存副本；取消不会写入照片。LIVE 原位点击播放、再次点击停止，自动播放必须静音。用户实测前仍保持候选状态。
