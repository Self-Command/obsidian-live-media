# Live Media 0.1.2：真实批次压缩与资源释放

本轮针对用户反馈的 `Aborted()`、解码失败和后续图片连锁失败。日期按 Asia/Shanghai 记录。待最终构建与实拍验证完成后填入产物及结果。

## 修改

- 普通 JPEG 默认压缩改用固定版本 libjpeg-turbo 的独立接口，逐行完整解码，质量参数直接映射到 JPEG quality；保留输入色度采样，输出后保留原 ICC / EXIF，继续做浏览器色彩比较。
- 编码、验证失败即丢弃 Worker；每个媒体结束后释放整个编码器实例，阻止上张照片的峰值堆和错误状态继续留在下一张。
- 视频验证禁用自动旋转，以原方向完成全部帧解码；`wrapped_avframe` 避免额外生成整帧 rawvideo 缓冲。实际压缩仍保留并核验原方向矩阵。
- Motion Photo 只有在所有帧展示时刻、帧数、尺寸和方向已一致时，才恢复末帧的原始时长；重建样本表和偏移后，再完整解码并校验音轨、色彩与时间。不能修复的布局仍保护跳过。
- 批次不再累计持有全部原图字节；仅保留临时结果和原件指纹。对比图滚动到可见区域才加载，离开或关闭后释放对象 URL 和播放资源；预览与提交时重新读取并核验原图。替换仍先备份、读回核验，原图有后续修改就拒绝覆盖。

没有降低原件指纹、完整解码、ICC 色彩、音轨、时间和默认 5% 节省比例的保护门槛。默认生成副本，不在源相册里试验覆盖。

## 本地实拍验证方式

用户指定相册全部复制到独立测试库，SHA256 核验。照片及带文件名的逐项结果仅保留在本机测试库，不提交公开仓库、CI 或远端服务。

`scripts/private-media-check.cjs` 启动独立 headless 浏览器，只允许访问随机令牌保护的 localhost 端点；加载从指定 Actions 下载并核验 SHA256 的 harness。每张编码、校验和输出均来自已构建的插件服务代码，不本地重新编译，不修改下载包。

序列验证调用相同 Compressor；批次验证调用实际 BatchService 的 prepare / commit，以默认副本输出并读回。CI 的合成样例和本机的私人实拍验证分别列出，不以浏览器测试冒充 Obsidian 或手机验收。
