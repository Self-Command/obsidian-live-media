# Live Media 0.1.3：逐张压缩与结果面板衔接

## 故障与责任

用户在实际 Obsidian 中完成整批临时压缩后遇到 `TypeError: this.isOpen is not a function`。0.1.2 的 Compressor 与 BatchService 测试通过，但没有覆盖 ScanModal → PrepareModal → CompareModal → CommitModal 的真正界面衔接，因此漏掉了这个阻断用户保存的错误。

旧 PrepareModal 定义 `private isOpen()` 并在准备完成后调用它。实际宿主上同名实例成员不是函数，调用因此失败。Obsidian 公开 Modal 契约只提供 open / close / onOpen / onClose 等接口，插件不应依赖或覆盖其未声明的内部成员。依据：[官方 Modal API](https://docs.obsidian.md/Reference/TypeScript+API/Modal)、[官方 API 声明](https://github.com/obsidianmd/obsidian-api/blob/master/obsidian.d.ts)。

## 修复

- 移除自定义 isOpen 方法，以本类独立 disposed 状态通过 onOpen / onClose 管理取消与卸载。
- 逐张读取、检查、压缩及完整校验；当前文件结束后才读下一张，相同路径去重，单张失败不取消其余图片。
- 界面显示当前文件、阶段、完成数量、成功、保护跳过与失败数量；进度条和滚动结果列表使用 Obsidian 主题变量。
- 所有原件只读，保存仍需用户最终确认。成功结果不因其他文件失败丢失。
- 先打开结果面板再关闭准备面板；结果面板初始化失败时保留已完成结果，单一操作按钮可重试，无需重新编码整批。
- 取消后不重新弹出结果，不写入图片。编码器、色彩、HDR、音轨、时间、文件指纹和备份校验沿用 0.1.2。

## 回归覆盖

单元测试明确验证：第一张结束前不读取第二张，路径去重，一张失败后继续下一张。

新增浏览器测试加载 Actions 构建的真实 main.js，通过模拟公开 Obsidian API 的宿主执行命令、选择、实际压缩、打开对比、确认副本及读回，而非只调用 Compressor。宿主 Modal 带有同名 isOpen 布尔实例字段，用于捕获本次碰撞。

覆盖正常流程（普通 JPEG、坏文件、Motion Photo）、取消、对比面板初始化故障及无需重编码的重试。实际 Obsidian、其他插件组合和移动端仍由用户核验；模拟宿主浏览器测试不冒充这些验收。
